## ROS 节点通信

```mermaid
flowchart LR
    METER["USB CDC 测厚仪"] <-->|"厂家协议字节流"| DEVICE["ThicknessDevice<br/>会话、周期请求、重连"]
    DEVICE <--> PROTOCOL["ThicknessProtocol<br/>组帧、CRC、解码"]
    DEVICE <--> SERIAL["SerialPort<br/>TTY 有界 I/O"]
    NODE["thickness_node<br/>ROS 适配"] -->|"process_io()"| DEVICE
    NODE -->|"/thickness/reading<br/>ThicknessReading"| MANAGER["measurement_manager_node"]
    NODE -->|"/thickness/status<br/>ThicknessStatus"| MANAGER
    MANAGER -->|"读数与状态变化"| TERMINAL["SSH / NoMachine 终端"]
```

`ThicknessDevice`、`ThicknessProtocol` 和 `SerialPort` 是同一采集进程内的 C++ 对象，不是 ROS 节点，也不创建 DDS 话题。

## 启动流程

```mermaid
flowchart LR
    USER["用户执行<br/>read_thickness.sh"] --> CHECK{"当前是否在开发容器"}
    CHECK -->|"宿主机"| DOCKER["复用或启动<br/>robot_ros2_dev"]
    CHECK -->|"容器内"| ENV["加载 ROS 与工作区环境"]
    DOCKER --> ENV
    ENV --> XML["measurement_manager/<br/>thickness.launch.xml"]
    XML -->|"device_path / baud_rate"| NODE["thickness_node"]
    XML --> MANAGER["measurement_manager_node"]
```

shell 脚本解决宿主机和容器环境差异；XML launch 负责声明启动参数并组合节点；C++ 节点负责运行逻辑。三者职责不能互相替代。

## 采集周期

```mermaid
sequenceDiagram
    participant TIMER as ThicknessNode 10 ms 定时器
    participant DEV as ThicknessDevice
    participant PORT as SerialPort
    participant PROTO as ThicknessProtocol
    participant PUB as ROS Publisher

    TIMER->>DEV: process_io(measurements)
    DEV->>PORT: 到期时 open_port()
    DEV->>PORT: read_bytes(timeout=0)
    PORT-->>DEV: 当前可用字节
    DEV->>PROTO: feed_bytes()
    PROTO-->>DEV: 有效帧
    DEV->>DEV: 识别设备、更新在线状态、提取测量
    DEV->>PORT: 到期时发送发现/心跳/状态查询
    DEV-->>TIMER: 本轮测量数组
    TIMER->>PUB: 转换并发布 ThicknessReading
```

状态由另一个 500 ms ROS 定时器读取 `ThicknessDevice::status()` 并发布。节点不重复实现通信判断。

## 当前 ROS 接口

| 接口 | 发布者 | 订阅者 | QoS | 用途 |
|---|---|---|---|---|
| `/thickness/reading` | `thickness_node` | `measurement_manager_node` | Reliable、KeepLast 64、Volatile | 发布 CRC 和字段校验后的原始读数 |
| `/thickness/status` | `thickness_node` | `measurement_manager_node` | Reliable、KeepLast 1、Volatile | 发布连接、在线、年龄和错误统计 |

状态为 `ONLINE` 只说明端口打开、设备已识别且最近应答未超时，不代表探头接触到位、机器人准备完成或计量精度合格。

## 当前边界

- `device_path` 和 `baud_rate` 是启动时只读参数，修改后需要重启节点。
- 当前没有统一参数管理节点、运行时热更新、测量启停服务或下位机就绪门控。
- `measurement_manager_node` 当前只打印，不发布滤波结果，也不写入本地文件。
- XRCE-DDS、数传和视频链路属于后续系统通信，不应塞入测厚节点。
