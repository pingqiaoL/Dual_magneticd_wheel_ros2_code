# 测厚节点使用说明

更新日期：2026-10-15。本文件对应简化后的当前代码；当天开发记录中的旧四包/滤波/CSV结果属于历史版本。

## 直接开始读取

脚本已支持宿主机和容器。先看提示符：nvidia@ubuntu通常是宿主机，robot@ubuntu:/workspace是开发容器。

在容器内直接执行，不需要安装Docker或退出VS Code开发容器：

```bash
bash /workspace/tools/read_thickness.sh device:=/dev/ttyACM0 baud_rate:=115200
```

在Orin宿主机终端执行（SSH或NoMachine均可）：

```bash
cd /home/nvidia/robot_ros2
bash tools/read_thickness.sh device:=/dev/ttyACM0 baud_rate:=115200
```

或者从任意宿主机目录执行：

```bash
bash /home/nvidia/robot_ros2/tools/read_thickness.sh
```

默认也是ACM0、115200。参数名称使用device和baud_rate，格式为名称:=值。设备路径是容器中的路径；其他USB端口需先在compose.yaml映射。当前Compose仍有原来的video0和ttyACM0映射，脚本不会更改设备映射。

在宿主机分支，脚本复用正在运行的dev容器，不因日常读取重建VS Code正在使用的容器；只有未运行时才调用compose up。启动后持续接收，Ctrl+C结束本次launch和两个节点。容器本身保留运行。

```bash
bash /home/nvidia/robot_ros2/tools/read_thickness.sh --help
```

只支持这两个启动选项；不在启动时自动编译，不实现参数统一管理或运行中热切换。宿主机与容器共享同一把工程锁，通过该脚本只能运行一份；它不能阻止另行手工运行的其他串口工具，因此不要同时打开厂商测试脚本读取同一设备。

## 输出含义

真实仪器握手后，本轮实机观察到：

```text
仪器状态: 通信正常，等待测量上报 | SN=CT260918B002 ...
```

有测量帧时，打印格式如下；数值49.25来自软件模拟测试，不是本轮仪器实测：

```text
测量: SN=CT260918B002 seq=1 value=49.25 unit=unknown material_raw=1 finite=true
```

- value：报文中大端float解码的原始值，保留9位有效数字打印。
- unit：当前采集节点固定unknown；需要与已知校准片和手机同步示值确认后再实现单位配置，不能先把所有值认作um。
- material_raw：材料原码，铁/铝映射未确认。
- finite：浮点数是否有限。NaN仍按原始消息打印为finite=false，不作为正常厚度。
- seq：本次采集节点收到的测量帧计数；进程重启清零，不是仪器原生序号，也不能证明仪器端未丢样。

状态只在连接状态、错误或首次测量等条件改变时提示，避免2Hz状态消息刷屏。每条测量在measurement_manager的订阅回调打印，采集节点不重复打印测量值。CRC错误帧不发布读数，错误计数通过状态报告。

“通信正常，等待测量上报”表示已有广播/心跳应答，但还没有本次连接的测量帧。贴合/抬离试块观察实际数据；通信正常不等于接触到位或精度通过。本轮没有实现校准、模式写入、滤波、CSV、业务启停、测量就绪门控和数传。

## 修改源码后的编译

本轮已完成编译，正常读取无需再编译。后续修改C++、消息或安装文件后，在宿主机执行：

```bash
cd /home/nvidia/robot_ros2
bash tools/dev.sh up
bash tools/dev.sh shell
```

进入容器后：

```bash
cd /workspace
source /opt/ros/jazzy/setup.bash
colcon build --packages-select robot_interfaces thickness_usb_driver measurement_manager --cmake-args -DBUILD_TESTING=ON
source /workspace/install/setup.bash
```

编译后可在当前容器运行/workspace/tools/read_thickness.sh，也可回到宿主机运行脚本。C++仍由编译器构建；XML只描述启动和传参，不是数据读取实现。

## 容器内直接启动

```bash
source /opt/ros/jazzy/setup.bash
source /workspace/install/setup.bash
ros2 launch measurement_manager thickness.launch.xml device:=/dev/ttyACM0 baud_rate:=115200
```

选择脚本或直接launch其中一种即可。当前XML已安装，不再依赖已删除的robot_bringup包。

## 消息和代码职责

| 类型/话题 | 字段或作用 |
| --- | --- |
| ThicknessReading /thickness/reading | received_at、sequence、device_sn[12]、value、unit、material_raw、finite |
| ThicknessStatus /thickness/status | stamp、connection_state、port_open、communication_ready、device_sn、应答/测量年龄、valid_frames、crc_errors、io_errors、last_error |

时间戳是Orin接收/发布时刻，不是仪器原生采样时刻；状态年龄使用本地steady_clock，尚未收到时是UINT32_MAX。读数使用Reliable/KeepLast64/Volatile，状态使用Reliable/KeepLast1/Volatile；不承诺无限历史或每个仪器事件都已保存。

采集节点10ms调度一次，每轮最多8次非阻塞读取；固定心跳1秒、应答超时3秒、重开1秒、状态查询5秒、每次写超时20ms，状态每0.5秒发布。只有device和baud_rate是只读启动参数，没有统一参数管理节点或动态参数回调。

底层UsbCdcPort构造只保存配置，openPort才打开Linux设备；端口读写与关闭在同一节点线程。ThicknessProtocol只解析协议，ByteRingBuffer只缓存组帧字节；当前没有样本历史环形缓冲或写盘线程。

## 当前测试

容器内运行底层测试：

```bash
cd /workspace
colcon test --packages-select thickness_usb_driver --event-handlers console_direct+
colcon test-result --verbose
```

两项测试覆盖协议分帧/CRC/恢复/异常值，以及端口伪终端读写/超时/回压/断开。本轮端到端模拟、宿主机退出测试和真实USB握手报告见10.15开发文档；测试日志与历史备份保存在log并排除Git。真实厚度端到端和计量精度仍待已知试片对照。
