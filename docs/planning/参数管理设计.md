# 参数管理设计（后续规划）

更新日期：2026-10-15。用户要求先完成简单采集和订阅打印，参数系统后续再添加。

## 当前实际实现

仅thickness_node声明device和baud_rate两个只读启动参数，XML提供默认值并接受命令行覆盖；sh原样透传。它们用于确定打开哪个设备和CDC线路编码，不是已经实现了一套统一参数管理系统。

没有robot_config_manager节点、参数保存/加载服务、测量启停参数、滤波/记录参数、单位切换、动态参数更新回调或MCU参数协议。原配置YAML已删除，默认值放在XML及节点启动声明中。当前读数单位固定unknown。

## 后续方向

- 各业务节点拥有自己的参数与校验逻辑，统一管理入口通过ROS标准参数服务访问，不复制一套取代节点真实值的全局参数数据库。
- 默认配置、运行时应用和显式持久化分别处理；参数被接受不代表硬件连接成功或已经保存。
- 可视化入口可在后续接入rqt或MK32数传界面；跨节点批量设置不等于全局事务，需要逐项报告。
- MCU参数仍属于下位机原有系统，需另定义请求/应答并实现XRCE链路；Orin保存文件不自动触发MCU Flash擦写。

本文件仅保留后续方向。每加入一部分，先明确职责、数据结构与生效策略，再按单文件步骤实现。不能将历史10.15旧版本中的measurement.enabled、filter和record参数当作当前可用配置。
