# 摄像头采集与视频上传

文档状态：现行
实现状态：已实现，模拟图像及真实摄像头本机回环验证通过
适用版本：2026-10-19 工作区未提交
更新日期：2026-10-19

## 目的与范围

同一 USB 摄像头只采集一次，向视频编码和后续视觉算法共享图像。当前实现 camera_driver 与 video_streamer_transmission；vision_processing 尚未创建。数传和视频是两条独立链路。

## 环境与约束

Orin Nano，宿主 R35.6.1，Ubuntu 24.04 / ROS 2 Jazzy 容器，GStreamer 1.24.2。Orin Nano 没有 NVENC，使用 x264enc CPU 软件编码。当前实际 USB 摄像头枚举为 MJPEG 和 YUYV，无 H.264：MJPEG 可 1280×720@30/60、1920×1080@30/60；YUYV 的 1280×720 仅列出 10 FPS。本轮只实测 MJPEG 1280×720@30。

## 结构与职责

| 层 | 文件 | 职责 |
|---|---|---|
| ROS 采集适配 | src/CameraCaptureNode.cpp | 启动参数、Image/CameraInfo/诊断消息、组件注册 |
| 设备会话 | module/CameraDevice.cpp | 唯一打开摄像头，采集线程，超时和重试 |
| ROS 视频适配 | src/VideoStreamerNode.cpp | 只读图像订阅、格式/年龄检查、启停服务、诊断 |
| 视频会话 | module/VideoStream.cpp | 最新帧槽、工作线程、RTSP 生命周期与资源清理 |
| 管线构建 | module/VideoPipeline.cpp | 参数范围检查，H.264/RTP 管线构建 |

普通 C++ module 不依赖 ROS 消息。图像通过 pixels/size_bytes/owner 只读引用传入，owner 保持像素内存有效，调用者不可修改共享像素。采集和视频组件加载到同一 component_container_mt，发布 unique_ptr，订阅 ConstSharedPtr 并开启进程内通信。GStreamer 到 ROS 紧凑图像、ROS 到 GStreamer 输入各有显式像素复制，不是整条管线零复制。

## 运行过程

采集工作线程构建 v4l2src → jpegdec（MJPEG）/avdec_h264（H264）→ videoconvert → BGR appsink。YUYV 使用 YUY2 caps。测试源必须显式 source_mode=test，使用 videotestsrc，不能标为真实摄像头。appsink 只保留最新一帧，采集按实际行跨度拷贝成无填充 bgr8。

采集节点发布 /camera/image_raw 和同时间戳 CameraInfo。CameraInfo 未标定，K[0]=0；时间戳为应用收到完整图像时的 ROS 时间，不是硬件曝光时间。

视频 ROS 回调检查 bgr8、分辨率、步长、字节数和 ROS 时间年龄，只提交引用。视频工作线程从单个最新帧槽消费，按目标帧率限速，复制到带正确行跨度元数据的 appsrc。编码路径：

```text
appsrc(BGR) → 有界原始帧队列 → videoconvert(I420)
→ x264enc(veryfast, zerolatency, B 帧关闭)
→ h264parse → rtph264pay → RTSP 客户端
```

RTSP factory 为 shared，同一 /live 地址的多个客户端共享一条编码管线。无客户端时相机继续发布，视频不会执行编码。不会在没有新图像时重复推送最后一帧。

## 接口与数据

详细参数、消息和 QoS 见 [ROS 接口参考](../reference/ROS接口与参数.md)。为复用标准工具，状态采用 diagnostic_msgs/DiagnosticArray，没有额外新增 VideoStatus.msg。

CameraDevice 构造函数验证并保存配置，不打开设备；start(callback) 创建工作线程并打开设备。callback 获得唯一 CameraFrame 所有权，在采集线程执行，应快速返回；stop() 唤醒并等待线程退出，允许随后重新 start。析构先 stop，复制被禁止。采集超时默认 2000 ms，失败后默认 1000 ms 重试。

VideoStream 构造函数校验配置及必要编码插件。start() 等待最多 3 秒获取 RTSP 启动结果；stop() 关闭监听、客户端和会话，清空待处理图像并等待工作线程退出；submit_frame() 快速保存图像引用和接收单调时间，覆盖旧待处理图像；status() 返回线程安全快照。start/stop 由同一 ROS 默认互斥回调组串行调用，不支持调用者并发执行生命周期操作。未启动时 submit_frame 不入队。

视频最大帧年龄默认 150 ms。原始图像的 DDS 和最新帧槽深度均为 1；appsrc 和编码前原始帧 queue 各最多保留 1 帧，过载丢旧帧。H.264 编码输出不按任意字节丢弃，IDR 附带参数集以便新客户端解码。

## 异常处理

- 设备不存在、启动失败、EOS、解码失败或无新图像：释放采集管线，报告 RECONNECTING 并重试。
- RTSP 端口占用：启动失败明确报告 ERROR；关闭后可重试启用。
- 输入无效或过期：不编码；输入停止超过超时后，已连接的视频端状态 WAITING_FRAME。
- 关闭视频服务不停止相机；采集可继续供视觉算法使用。
- 停止进程时先终止工作线程并释放摄像头、媒体会话和监听端口。

## 已知限制

- 本轮不是长期性能验收，30 FPS 和 2000 kbps 是目标配置，不是所有负载下的测得保证。
- 当前只支持同一配置分辨率的紧凑 bgr8 输入；不提供录像、视觉算法或 H.264 原码流直通。当前设备未列出 H.264 输出。
- 两个本机解码器仅证明视频格式与服务可用，不代表天空端网络透传和安卓播放器成功。
- 物理 USB 拔插未测试。若拔插后宿主设备节点重新创建，Docker 的设备绑定可能需要重建容器；节点内部重试不能修复容器外的设备映射。
- 当前解码样例画面模糊，光学对焦、照明和真实画质待验证。CameraInfo 尚未标定，不能直接用于几何测量。
