# 测厚管理与 MK32 数传

文档状态：现行；更新日期：2026-10-22。
本轮驱动线程重构的编译与软件测试结果见 [当天开发记录](../2026-10-22开发文档.md)。

## 职责与数据流

`thickness_node → /thickness/reading → measurement_manager_node → /measurement/thickness → telemetry_bridge_node → MAVLink 串口 → MK32`。

| 模块 | 职责 |
|---|---|
| ThicknessNode / ThicknessDevice | 持续读取仪器、解析、发布原始读数和仪器状态；仪器协议心跳在设备层 |
| MeasurementManagerNode | 保存启停布尔量，开启期间转发每条有效新读数并打印 |
| TelemetryBridgeNode | 订阅并校验业务数据，提交 THICKNESS 和 STM_LINK |
| TelemetryDriver | 后台线程、事件等待、串口重连、有界队列、过期丢弃、MAVLink 心跳及应答 |
| RemoteProtocol | MAVLink common 子集编码、CRC、拆帧、PING/ACK |

manager 当前默认开启。下位机状态订阅未启用；未来在本节点订阅回调调用 `on_measurement_ready(bool)`。true 持续发布，false 停止产生新结果；重复 true 不重置开启时间。驱动在关闭业务输出后仍持续读取。没有新读数就没有新结果；两条数值相同的新消息仍分别发送。当前未滤波、未存储，单位统一 µm。

manager 仅保留数据发布器、读数订阅器、布尔开关和开启时刻。`MeasurementManagerNode.cpp` 同时包含节点实现和 main 入口；订阅回调名为 `update_data()`。测试目标通过专用编译宏排除正式入口，由测试程序提供 main。没有 UUID、会话号、周期号、控制发布定时器或测厚启停服务。`/thickness/status` 保留供诊断工具订阅，manager 不再承担仪器状态解释。

## 消息与协议

manager 与数传节点直接使用 `ThicknessReading`，不再使用只包装一层的 `MeasurementResult`。原始序号、接收时间、设备 SN 等信息完整保留。两个测量话题均为 Reliable / Volatile / KeepLast64。不再提供 `/measurement/control`、MeasurementControl 或 `/measurement/set_enabled`。

数传发送未签名 MAVLink 2，源地址 1/191；只响应安卓源地址 255/190 的 PING 和当前命令子集。

| 消息 | 内容与触发 |
|---|---|
| NAMED_VALUE_FLOAT / THICKNESS | 每条有效新结果一次；单位 µm |
| HEARTBEAT | 1 Hz，与是否收到测量数据无关 |
| PING | 保留请求时间和序号，目标为请求方 |
| COMMAND_ACK | 未实现命令返回 MAV_RESULT_UNSUPPORTED=3 |
| NAMED_VALUE_INT / STM_LINK | 应用节点每 1 秒提交固定 0；真实下位机尚未接入 |

`STM_LINK` 属于下位机业务状态，由应用节点提供；驱动不能从串口打开状态推断 STM32 在线。当前真实下位机尚未接入，所以应用固定提交 0。不再发送 MEAS_RUN，因为数传驱动不持有 manager 开关；不能从“暂时无读数”推断关闭状态。

## 驱动线程与事件等待

应用调用 `send_named_float()` 或 `send_named_int()` 时只进行校验、入队和唤醒，返回值表示是否接受入队，不表示串口或安卓已经接收。串口打开、读写、关闭均由 `TelemetryDriver` 的单个工作线程负责。

驱动使用 `poll()` 同时等待串口描述符和内部 `eventfd`：串口可读时接收报文，有待发数据时才监听可写事件，应用提交数据或请求停止时由 `eventfd` 立即唤醒。等待超时由下一次心跳、重连或遥测过期截止时间决定，不再由 ROS 10 ms 定时器推进通信。

`SerialPort::native_handle()` 仅把当前描述符借给同一所有者线程执行就绪等待，不转移所有权。外部唤醒、线程、队列、心跳和重连仍属于数传驱动。

## 排队、取消与异常边界

- manager 拒绝开启前已接收的旧读数；只在 false→true 时更新开启时间。
- 数传拒绝来源接收时间在未来或已超过 1000 ms 的测厚数据；未开始发送的串口队列帧排队超过 1000 ms 也丢弃。这是两个分别检查的门限，不是端到端 1 秒保证。
- 实时遥测队列最多 64 帧，满时丢最旧未发送帧并计数。断线期间不积压，重连后等待新数据。未来需要确认的命令必须使用独立接口和策略。
- 串口每次唤醒后执行有限量读写；订阅回调不等待串口。部分写入的帧完成后再发下一帧，sequence 按真正发送顺序分配。
- false 只停止 manager 后续发布，已进入 DDS、数传队列、系统串口或无线链路的数据不能通过此布尔量撤回。已排队数据可能继续发出直至排空或过期，不承诺取消瞬间无线零输出。
- manager 退出后没有新结果，不再有独立 2 秒开关心跳超时；串口在线心跳继续。任何合法新结果发布者都会被数传接收，不再进行旧会话/周期隔离。
- `written` 表示整帧交给本机串口，不表示安卓确认接收。当前没有持久化、应用层确认或历史补传。
