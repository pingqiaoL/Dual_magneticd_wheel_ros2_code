## 1. 环境和依赖

代码在宿主 `/home/nvidia/robot_ros2`，容器 `/workspace`。默认 /dev/video0 已由 Compose 映射；容器 robot 用户需要 video 组。不要同时用拍照软件打开同一设备。

Dockerfile 已加入 GStreamer 和测试依赖。本轮已经在当前容器安装；以后重建开发镜像也会安装。若在旧容器缺少依赖，在 Orin 宿主机执行：

```bash
docker exec -u 0 robot_ros2_dev bash -c 'apt-get update && apt-get install -y --no-install-recommends libgstreamer1.0-dev libgstreamer-plugins-base1.0-dev libgstrtspserver-1.0-dev gstreamer1.0-tools gstreamer1.0-plugins-base gstreamer1.0-plugins-good gstreamer1.0-plugins-bad gstreamer1.0-plugins-ugly gstreamer1.0-libav v4l-utils python3-gi gir1.2-gstreamer-1.0 gir1.2-gst-plugins-base-1.0'
```

检查（宿主机或容器均可）：

```bash
bash tools/inspect_camera.sh /dev/video0
```

预期列出 MJPG/YUYV 支持模式，必要插件全部可用。当前设备已验证 MJPEG 1080p60采集、1080p30编码；其他格式和分辨率以设备枚举为准。

## 4. 播放与状态

使用支持 RTSP 的播放器打开：

```text
rtsp://<客户端可访问的Orin_IP>:8554/live
```

客户端优先使用 RTP over RTSP/TCP 进行初次联调。连接后才开始编码；相机启动后持续采集。当前 Wi-Fi 地址为 192.168.74.236；天空端四线连接和独立供电后，eth0 已协商到 100 Mb/s 全双工，并通过 DHCP 获得 192.168.144.129/24，图传网段播放地址为 `rtsp://192.168.144.129:8554/live`。DHCP 地址可能变化，应先用 `ip -br address show eth0` 核对。Orin 到默认天空端 .11、地面端 .12 的短时 ping 已通过；默认安卓地址 .20 未应答且 ARP 失败，安卓地址和路由仍需确认，实际无线视频播放尚未验收。

另一个容器终端：

```bash
source /workspace/install/setup.bash
ros2 topic echo /camera/status
ros2 topic echo /video/status
```

依次执行或使用不同终端。采集状态应为 CAPTURING；无客户端时视频 LISTENING，有近期编码输出时 STREAMING。状态并不代表安卓解码成功。

启停视频服务：

```bash
ros2 service call /video/set_enabled std_srvs/srv/SetBool '{data: false}'
ros2 service call /video/set_enabled std_srvs/srv/SetBool '{data: true}'
```

false 关闭 RTSP 服务但相机继续采集。true 重新监听，客户端需重新连接。停止整个视频进程，在启动脚本终端按 Ctrl+C。

## 6. 后续视觉订阅

订阅 /camera/image_raw（sensor_msgs/msg/Image），使用 SensorDataQoS().keep_last(1)，回调采用 Image::ConstSharedPtr。算法工作线程只保留最新图像引用；需要画框或修改像素时复制自己的图像。相机内参未标定，不能直接用于尺度/位姿测量。

## 7. 失败时检查

| 现象 | 检查 |
|---|---|
| 摄像头 RECONNECTING | 查看 last_error、设备映射、是否被占用、格式/帧率是否受支持 |
| RTSP 启动失败 | 检查编码插件、端口占用和配置范围 |
| LISTENING | 尚无 RTSP 连接，不是摄像头故障 |
| WAITING_FRAME | 检查 /camera/status 和图像分辨率/编码/时间年龄 |
| 本机能播放，安卓不能播放 | 检查 eth0 物理链路、IP、天空端网络透传和安卓实际播放器 |
| 有画面但模糊 | 对准有纹理目标，检查焦距、保护膜、镜头清洁和光照；不能用分辨率数字代替画质验收 |

本仓库未实现录像、视觉算法或视频开机自启动。安卓播放器由独立仓库维护，接收端反馈已接入 RTSP；无线播放、时延和长期 CPU/温度仍待实测验收。

## 8. MK32 安卓仅有回环地址或 Network is unreachable

先在遥控器安卓“设置 → 网络和互联网 → 以太网”启用以太网，检查状态栏标志及实际 IP。用户提供的 MK32 手册 6.9 节（PDF 第 145 页）将该开关列为无图像时的排障步骤。安卓需要实际网络接口和 192.168.144.x 地址；127.0.0.1 是本机回环，不能访问 Orin。

在连接 MK32 ADB 的 Ubuntu 虚拟机执行：

```bash
~/Android/Sdk/platform-tools/adb shell ping -c 3 192.168.144.129
```

如果不通，继续只读检查：

```bash
~/Android/Sdk/platform-tools/adb shell ip addr
~/Android/Sdk/platform-tools/adb shell ip route
~/Android/Sdk/platform-tools/adb shell dumpsys ethernet
```

区分接口是否存在、以太网是否启用、是否取得地址及是否有到目标的路由。以太网设置与思翼 UART 数传设置是两项不同配置。Orin 已显示 LISTENING 时保持现有视频进程，先恢复安卓网络，再由播放器重新连接。接收端后续反馈 v0.7.0 已接入 RTSP 播放，但本仓库没有独立验收该 APK 或安卓实际画面。
