## 输出含义

真实仪器握手后，本轮实机观察到：

```text
仪器状态: 通信正常，等待测量上报 | SN=CT260918B002 ...
```

有测量帧时，打印格式如下；数值49.25来自软件模拟测试，不是本轮仪器实测：

```text
测量: SN=CT260918B002 seq=1 value=49.25 unit=um material_raw=1 finite=true
```

- value：报文中大端float解码的原始值，保留9位有效数字打印。
- unit：当前采集节点固定发布 um（µm），数值直接来自仪器解码，不进行缩放。
- material_raw：材料原码，铁/铝映射未确认。
- finite：浮点数是否有限。NaN仍按原始消息打印为finite=false，不作为正常厚度。
- seq：本次采集节点收到的测量帧计数；进程重启清零，不是仪器原生序号，也不能证明仪器端未丢样。

状态只在连接状态、错误或首次测量等条件改变时提示，避免2Hz状态消息刷屏。每条测量在measurement_manager的订阅回调打印，采集节点不重复打印测量值。CRC错误帧不发布读数，错误计数通过状态报告。

“通信正常，等待测量上报”表示已有广播/心跳应答，但还没有本次连接的测量帧。贴合/抬离试块观察实际数据；通信正常不等于接触到位或精度通过。当前未实现校准、模式写入、滤波、CSV 和真实下位机控制；manager 默认开启并支持调试服务，数传见专项指南。

## 修改源码后的编译

本轮已完成编译，正常读取无需再编译。后续修改C++、消息或安装文件后，在宿主机执行：

```bash
cd /home/nvidia/robot_ros2
bash tools/dev.sh up
bash tools/dev.sh shell
```

进入容器后：

```bash
cd /workspace
source /opt/ros/jazzy/setup.bash
colcon build --packages-up-to measurement_manager --cmake-args -DBUILD_TESTING=ON
source /workspace/install/setup.bash
```

编译后可在当前容器运行/workspace/activate/single_module/thickness.sh，也可回到宿主机运行脚本。C++仍由编译器构建；XML只描述启动和传参，不是数据读取实现。

## 容器内直接启动

```bash
source /opt/ros/jazzy/setup.bash
source /workspace/install/setup.bash
ros2 launch measurement_manager thickness.launch.xml device_path:=/dev/ttyACM0 baud_rate:=115200
```

选择脚本或直接launch其中一种即可。当前XML已安装，不再依赖已删除的robot_bringup包。

## 消息和代码职责

| 类型/话题 | 字段或作用 |
| --- | --- |
| ThicknessReading /thickness/reading | received_at、sequence、device_sn[12]、value、unit、material_raw、finite |
| ThicknessStatus /thickness/status | stamp、connection_state、port_open、communication_ready、device_sn、应答/测量年龄、valid_frames、crc_errors、io_errors、last_error |

时间戳是Orin接收/发布时刻，不是仪器原生采样时刻；状态年龄使用本地steady_clock，尚未收到时是UINT32_MAX。读数使用Reliable/KeepLast64/Volatile，状态使用Reliable/KeepLast1/Volatile；不承诺无限历史或每个仪器事件都已保存。

采集节点每 10 ms 调用一次 `ThicknessDevice::process_io()`，设备层每轮最多执行 8 次非阻塞读取；固定心跳 1 秒、应答超时 3 秒、重开 1 秒、发现 3 秒、状态查询 5 秒、每次写超时 20 ms，状态每 0.5 秒发布。只有 `device_path` 和 `baud_rate` 是只读启动参数，没有统一参数管理节点或动态参数回调。

`ThicknessNode` 只负责 ROS 适配；打开设备、重连和在线判断由 `ThicknessDevice` 完成。底层 `robot_common::io::SerialPort` 构造只保存配置，`open_port()` 才打开 Linux 设备。`ThicknessProtocol` 只解释协议，`robot_common::buffer::ByteRingBuffer` 只缓存组帧字节；当前没有样本历史环形缓冲或写盘线程。
