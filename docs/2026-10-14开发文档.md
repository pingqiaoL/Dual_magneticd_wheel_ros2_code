### 技术选择

- 保留宿主机与 JetPack，ROS 运行在容器内，不向 Ubuntu 20.04 添加其他 Ubuntu 版本的软件源。
- 本次选择 ROS 2 Jazzy / Ubuntu 24.04 ARM64 容器。Jazzy 社区支持期至 2029 年 5 月；此前 README 中的 Humble 是初步建议，尚未安装。
- 宿主机使用当前 Ubuntu 软件源提供的 `docker.io` 和 `docker-compose-v2`，不混装 Docker CE。
- 先验证 CPU 上的 ROS 节点、开发工具和基础通信。NVIDIA GPU、多媒体库、摄像头和真实串口访问不包含在本轮已验证范围。
- 开发代码保存在宿主机，容器挂载工作空间；应用日志与构建结果不提交到 Git。

### 安装与配置过程

1. 检查系统版本、CPU 架构、资源、Git 工作区和宿主机软件包候选版本。
2. 编写 `tools/install_docker_host.sh`。用户在 Orin 本机终端以 sudo 执行，密码只在本机输入。
3. 用户在本机终端完成 sudo 安装。重新建立 SSH 会话后，实测 Docker 26.1.3、Compose 2.27.1 可运行，用户已属于 docker 组，存储驱动为 overlay2。
4. 初版安装脚本未包含 Buildx，补充为 `docker-buildx`；当前开发用户通过 `tools/install_user_buildx.py` 下载 Ubuntu 源内对应软件包，验证 SHA256 后提取到用户缓存目录并安装用户级插件，实测版本 0.14.1。没有配置 sudo 免密。
5. Orin 直接访问 Docker Hub 超时；Windows 能读取官方 ROS 镜像索引，Orin 能访问 ECR。核对 ECR 上 ARM64 manifest 的 SHA256 与 Docker Hub 官方索引一致后，使用固定摘要的副本下载，记录到 `docker/base-image.lock.json`。
6. 添加 Dockerfile、Compose、VS Code 开发容器配置、环境脚本和操作文档，配置非 root 开发用户、工作区挂载、DDS 本机发现和日志轮转。
7. Windows VS Code 安装 Dev Containers 扩展；Shell 语法、Python 语法、JSON、Compose 配置与 Git whitespace 检查均通过。
8. PyPI 上的 ARM64 wheel 下载缓慢，初次构建在下载阶段停止。保留已经完成的 APT 构建缓存，将 pip 配置为 TUNA HTTPS 镜像，并固定 `pymavlink=2.4.50`、`fastcrc=0.5.0`、`pyserial=3.5`，随后重建成功。
9. 创建 `robot_ros2_dev` 容器，实际用户为 `robot`、UID/GID 为 1000，工作目录 `/workspace` 对应宿主机工程。未启用 privileged 模式，未映射真实硬件设备。
10. 运行 `tools/verify_dev_environment.py`：真实生成并编译临时 C++ ROS 包，由 Python 节点接收随机标记消息，再完成 MAVLink 2 HEARTBEAT 本地编解码。测试进程退出后清理临时目录，业务 `src` 保持为空。
11. 重启开发容器后，验证 ROS 命令和 Python MAVLink 库仍可使用。宿主机验证报告文件属于 `nvidia:nvidia`，未产生 root 所有的工作区文件。

### 使用方式

在 Orin 宿主机的 VS Code 远程终端中执行：

```bash
cd ~/robot_ros2
bash tools/dev.sh shell
```

需要重新验证基础环境时，在宿主机执行：

```bash
cd ~/robot_ros2
bash tools/dev.sh verify
```

构建日志与测试结果保存在宿主机 `log/`，已经由 Git 忽略。主要文件：`docker-build-2026-10-14.log`、`docker-build-2026-10-14-tuna.log`、`environment-verification.json`。
