# ADR-0001：测厚模块采用组合式分层

状态：已接受  
日期：2026-10-16

## 背景与问题

原 `ThicknessNode` 同时负责 ROS 参数与发布、TTY 打开关闭、重连、协议解析、设备识别、心跳和状态判断。节点难以阅读，设备状态逻辑也难以在脱离 ROS 的情况下测试。与此同时，项目后续会接入其他串口设备和 USB 摄像头，需要明确可复用边界。

## 考虑的方案

### 方案 A：保持单一节点类

修改量小，但职责继续增长，设备错误恢复只能通过 ROS 节点测试。

### 方案 B：建立覆盖串口、USB 和摄像头的统一设备父类

表面上可以统一 `open()` 和 `close()`，但 TTY 字节流、USB 摄像头流和具体仪器会话的资源及错误语义不同，父类无法提供稳定而有价值的行为契约。

### 方案 C：按职责分层并通过组合连接

提取通用 `SerialPort` 和 `ByteRingBuffer`；`ThicknessProtocol` 只处理协议；`ThicknessDevice` 组合串口与协议并管理会话；`ThicknessNode` 只做 ROS 适配。

## 决定

选择方案 C。当前不建立统一设备父类，也不为单一后端增加 `ByteTransport` 虚接口。未来同一仪器确实需要串口、TCP 等多个可替换字节传输后端时，再根据已经出现的共同契约提取传输接口。摄像头保持独立的 V4L2/编解码架构。

## 结果与代价

积极结果：

- 节点不再判断打开失败、在线超时和重连。
- 设备业务层能够通过伪终端独立测试。
- 其他 TTY 设备可以复用底层读写和字节缓冲。
- 协议常量集中在 `ThicknessProtocol.cpp` 内部，减少重复定义。

代价：

- 新增设备层和普通 C++ 状态结构，文件数量增加。
- `ThicknessDevice` 当前仍是同步有界 I/O，需要后续根据性能数据决定是否线程化。
- `SerialPort` 首版串口配置仍固定为 raw、8N1、无流控。

## 确认方式

- ROS 节点源码中不得直接调用 `open_port()`、`read_bytes()` 或判断协议在线状态。
- 设备层测试覆盖打开、协议应答、在线状态和断线恢复。
- 公共串口测试覆盖 TTY 资源和超时语义。
