# 摄像头与测厚仪接入说明

文档状态：现行参考  
更新日期：2026-10-16。测厚仪已识别为 CDC ACM（`28e9:018a`、`/dev/ttyACM0`），测厚软件链路已完成模拟验证；无线图传仍未实现。

## 测厚仪资料结论

用户提供的 M 系列产品资料介绍 mCT350 智能涂层测厚探头：探头内部完成采集与处理，手机 APP 提供显示、保存和报告；资料注明可开放通信协议，支持通过 USB Hub 连接多个 M 系列设备。

因此可考虑让 Orin 作为 USB 主机，直接读取探头，ROS 节点负责解析和发布测厚数据；不需要把原始模拟信号送入 STM32。USB 类别和 Linux 兼容性仍需实测，手机 APP 可用不等于已有 Linux 驱动。

产品资料未提供 VID/PID、USB 接口类型、端点地址、CRC 细节或 Linux SDK。不能只凭 Type-C 外形判断是串口，也不能预设波特率。

## USB 协议使用顺序

1. 在宿主机确认 USB 枚举，读取 VID/PID、接口类别、驱动和端点。当前测厚仪由 `cdc_acm` 驱动生成 `/dev/ttyACM0`。
2. CDC/USB 串口使用对应 tty 设备；HID 使用 hidraw/HIDAPI；厂商自定义接口根据端点使用 libusb。根据实际接口决定，不提前选定。
3. 接收原始字节，缓存并定位帧头，按确认后的长度拆帧，验证帧尾和 CRC，再解析消息类型与数据。处理分包、连续多帧、超时与拔插重连。
4. 先做只读测量接收或经确认的状态查询，再开发校准写入功能。
5. 发布带时间戳、厚度、单位、材料类型与有效状态的 ROS 消息。测量值为零和设备断连必须分别表示。
6. 通过数传发送选定的测厚结果、时间戳与状态；Orin 到 STM32 的目标通信已调整为 XRCE-DDS；地面数传仍需独立约定报文。原厂 USB 帧不会自动变成 ROS/DDS 或地面数传消息。

原厂 USB 协议文档中的待确认项：

- 测量数据帧头为 FE E1 90 0D，帧尾为 0D 90 E1 FE，功能类别列为 05。
- 序列号 12 字节、材料类型 u8 与 float 厚度合计 17 字节，而文档数据长度写 16、总长写 44，存在冲突。
- CRC 只给出 2 字节字段，未说明多项式、初值、输入范围、反射和输出字节序；float 字节序与单位也需确认。
- 测量上报的发送方说明、材料枚举注释及若干响应类别存在互相矛盾的表述。

需向厂家索取与当前固件一致的协议、USB 描述符/SDK、CRC 参考实现及有效的收发十六进制样例；不发送按猜测拼接的配置或校准报文。

## 视频编码与传输

本次通过只读 V4L2 格式枚举，/dev/video0 支持 MJPG 和 YUYV；/dev/video1 未枚举出普通视频采集格式。两者归属于同一个 USB 摄像头接口，不能据此认为是两台摄像头。尚未采集图像或验证实际帧率、分辨率。

网口图传的建议路径：USB 摄像头 → Orin 采集 → H.264 编码及网络封装 → LAN → 天空端 → 地面端 → UI 解码显示。具体 RTSP/RTP 地址、编码支持和码率限制需按实际图传配置确认。

MJPEG 已经是逐帧压缩视频，但通常仍需解码后转成 H.264 以适配接收端并降低无线带宽。若换成可直接输出兼容 H.264 的摄像头，可能只需封装转发。网口本身不会自动将原始视频压成 H.264。

实测设备树 model 为 NVIDIA Orin Nano Developer Kit。Orin Nano 无 NVENC 硬件编码器，不能直接套用 Orin NX 的硬件编码方案。可从软件 H.264、720p/30fps、约 2–4 Mbps 的候选配置开始评估，之后根据 CPU、图像清晰度、无线链路和端到端延迟实测调整；这不是已验证性能。

参考：[NVIDIA Orin Nano 软件编码说明](https://docs.nvidia.com/jetson/archives/r35.6.0/DeveloperGuide/SD/Multimedia/SoftwareEncodeInOrinNano.html)。

## Docker 边界

当前开发容器按 `compose.yaml` 映射 `/dev/video0` 和 `/dev/ttyACM0`，并使用 `video`、`dialout` 组访问。设备节点变化时应修改映射并重建容器；不默认开放全部 USB 或使用 `privileged`。

后续视频若使用宿主机 JetPack 的多媒体库，需要按 JetPack 版本设计运行环境，不能假设 Jazzy/Ubuntu 24.04 基础容器已经包含可直接使用的全部 Jetson 多媒体组件。

## SerialPort 已实现接口

最初的 `UsbCdcPort` 已在 2026-10-16 泛化为 `robot_common::io::SerialPort`。它是 TTY I/O 适配器，不包含测厚协议；真实设备识别结论不等于重构后的实机通信已经回归。

```cpp
robot_common::io::SerialPort serial_port(device_path, baud_rate);
if (!serial_port.open_port())  // 此处才执行设备 I/O
{
    // 由调用者读取 last_error()/last_error_code()，决定何时重试。
}
```

`read_bytes(buffer, capacity, timeout_ms)` 返回本次实际字节数；0 表示等待结束没有数据；-1 表示错误。读取不保证填满缓冲区或得到完整报文。`timeout_ms` 非负，0 为即时检查；断开或不可恢复的 I/O 错误关闭描述符，调用者可稍后再次 `open_port()`。参数错误不关闭设备，错误信息在下一次成功操作或正常超时后清除。

路径和波特率在对象生命周期中固定；后续参数更新按停止读取、关闭旧对象、用新配置构造并重新打开的顺序处理。不可从另一线程直接关闭一个正在读取的对象。`is_open()` 不执行在线探测，物理断开需要后续 I/O 发现。

支持 9600、19200、38400、57600、115200、230400、460800 和 921600。它们不等于 USB 总线速率。当前类不写入厂商业务命令、不解析 CRC、不发布 ROS 消息；设备发现、心跳、协议解析和重连由 `ThicknessDevice` 与 `ThicknessProtocol` 完成。
