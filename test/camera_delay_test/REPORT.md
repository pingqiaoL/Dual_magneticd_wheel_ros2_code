# 摄像头延迟实测报告

日期：2026-10-20。设备：Orin Nano，真实 USB 摄像头。每组预热 10 秒、正式统计 60 秒，共五组。

## 结论

本轮没有观察到 Nano 已测软件路径存在 300～400 ms 的持续积压。原 CV 方式从 V4L2 输出到 GUI 调用返回约 29 ms；视频编码路径约 45 ms。这个结果不覆盖曝光、摄像头内部缓存、完整 USB 驱动等待、物理屏幕刷新、无线传输及安卓播放缓存。

最新帧 CV 对照没有明显降低当前稳态延迟，因此不能认定原查看器的 5 帧队列是本轮主要瓶颈，正式查看器未修改。整机组中 CV 接收/显示约 24.8 FPS，而编码约 29.9 FPS，说明查看器帧率不能代替视频编码帧率。

## 数据可信度

- 正式源码 SHA256 与测试开始前一致；计时点仅加入独立副本。测试采用正式构建的空 CMAKE_BUILD_TYPE，编码参数保持 720p30、6000 kbit/s、GOP 30、B 帧 0。
- 统一使用 CLOCK_MONOTONIC。ROS header 时间仅作为帧 ID；采集 PTS、ROS 帧 ID 和编码 PTS 建立关联。D/E 编码输入与输出经固定 PTS 偏移校正后，精确匹配率均为 100%。
- 预检查的 Release 构建已中止，其数据不纳入报告。D 首次尝试因测试接收器早于 RTSP 就绪而失败，修正等待条件后完整重测 D/E；失败目录保留用于排错，汇总不包含它们。
- 分析器的三个边界测试通过：预热剔除与正确帧配对、错误编码配对拒绝、负耗时拒绝。计时/日志开销尚未通过完全无埋点的等负载试验量化。
- 每种配置仅完成一次 60 秒有效采样，不能将小幅组间差异当成可重复的优化收益。B/C 还同时改变队列与线程方式。

## 整机组的限制

E 组测厚与数传节点均启动，数传串口已打开；但测厚仪出现 `request write incomplete: write deadline expired: Connection timed out`，没有新测量数据上报。因此 E 组代表模块进程同时运行及视频负载，尚未覆盖真实测厚数据满负荷。恢复正式程序后仍出现该 USB 写超时，应另行检查仪器连接及状态。

测试经回环 RTSP/TCP 接收器持续拉流至 fakesink，确保编码工作；该接收器不做 H.264 解码与屏幕显示。本轮未验收遥控器的无线延迟或播放缓存。

## 与用户照片对照

照片中原计时器 19.89 s、Nano 直连 CV 画面 19.75 s、遥控画面约 19.52 s，分别估计为 140 ms 和 370 ms。这是用户提供的单张实拍样本，本轮没有重新自动拍摄端到端照片。

软件测到的约 29 ms 或 45 ms 与照片的计时边界不同，不能直接相减后把剩余时间全部归给某个设备。照片提示的 CV 与遥控器差值约 230 ms，包含视频分支、无线传输和安卓解码/播放/呈现差异。

后续排查优先补充：

1. 使用同一计时器至少拍摄 20 组原画面、Nano 直连画面、遥控画面，得到端到端延迟分布。
2. 若继续定位 Nano 的 100 多 ms，检查曝光和摄像头内部/驱动缓存，并使用物理呈现测量；当前 GUI 返回计时不包含真实显示完成。
3. 安卓记录同一帧从接收、送解码到实际呈现的时间，先在安卓自身单调时钟内计算；跨设备测单向网络耗时须时钟同步或其他校准。
4. 本轮没有证据支持通过增大码率或盲目缩短 GOP 来消除固定延迟，暂不更改编码配置。
