# 2026-10-23 1080p 图传延迟优化测试

## 目标与边界

目标是在不修改正式源码的前提下，对 1920×1080、30 FPS 图传做隔离测试，验证机载编码路径、视觉分支负载、无线码率和安卓播放缓冲。所有机载改动均由 `test/camera_delay_optimize` 复制源码到临时工作区后编译；正式 `src/` 未修改。

软件计时从 V4L2 输出开始，到 H.264 编码输出结束，不含摄像头曝光/内部缓存、无线传输、安卓解码和屏幕刷新。端到端 200 ms 是否达成，仍须同屏计时器或高帧率录像确认。

## 机载端结果

| 方案 | 采集 FPS | 编码 FPS | V4L2→H.264 中位/P95 | CPU 中位 | 结论 |
|---|---:|---:|---:|---:|---|
| BGR + veryfast/自动线程 | 29.90 | 22.90 | 88.89 / 106.12 ms | 56.45% | 不能保持 30 FPS |
| BGR + superfast/2 线程 | 29.90 | 28.00 | 111.22 / 131.26 ms | 48.88% | 仍掉帧且等待更长 |
| BGR + ultrafast/2 线程 | 29.87 | 29.90 | 85.51 / 89.92 ms | 37.42% | BGR 路径中的最佳编码器参数 |
| BGR + ultrafast/1 线程 | 29.90 | 23.33 | 87.85 / 103.68 ms | 33.00% | 单线程吞吐不足 |
| I420 直通 + ultrafast/2 线程 | 29.90 | 29.87 | 58.11 / 63.23 ms | 25.47% | 去除编码前 BGR→I420 转换有效 |
| I420 + 独立 BGR 视觉分支 | 29.87 | 29.87 | 57.52 / 62.53 ms | 29.64% | 两分支均稳定约 29.9 FPS |
| 上述双分支，4 Mbps 实链路 | 29.88 | 29.88 | 57.80 / 62.94 ms | 29.67% | eth0 中位 4.15 Mbps，编码延迟无明显变化 |

有效的视觉负载轮次中，BGR 分支连续记录 29.86–29.90 FPS。I420 分流相对 BGR 最佳方案把机载中位耗时降低约 28 ms，且没有牺牲编码或视觉帧率。

原始结果：

- `results/run_20261023_114440`：四组 BGR 编码器参数。
- `results/run_20261023_115102`：I420 单编码分支。
- `results/run_20261023_115730`：I420 编码与 BGR 视觉双分支。
- `results/run_20261023_121405`：4 Mbps、真实以太网客户端。
- `results/run_20261023_121754`：4 Mbps 重复轮次。

`run_20261023_115406` 的视觉探针未加载，结果只作为失败记录，不用于双分支结论。

## 安卓端结果

| APK/码率 | 稳态缓冲中位/P95 | 渲染 FPS | 稳态短欠载 | 解码丢帧 | 结论 |
|---|---:|---:|---:|---:|---|
| 正式 100/180，4 Mbps | 162 / 179 ms | 29.90 | 6 次，合计 197 ms | 0 | 本轮稳定性最佳 |
| gentle90，6 Mbps | 158 / 193 ms | 29.87 | 46 次，合计 1729 ms | 0 | 仅降 4 ms，卡顿显著增加 |
| gentle90，4 Mbps | 151 / 182 ms | 29.92 | 37 次，合计 961 ms | 0 | 降码率有小幅改善，仍不可接受 |
| stable120，4 Mbps | 163 / 233 ms | 29.99 | 18 次，合计 379 ms | 0 | 未降低中位缓冲，稳定性更差 |

测试策略：

- `gentle90`：目标 90 ms、触发 150 ms、持续 200 ms、1.04×/1.10×。
- `stable120`：目标 120 ms、触发 170 ms、持续 200 ms、1.03×/1.08×。
- `balanced75` 已完成构建与单元测试，但 `gentle90` 已证明更低目标会持续触发欠载，因此没有安装运行。

安卓三组隔离候选均通过 34 项单元测试。测试结束后恢复已备份的正式 0.8.10 APK。

## 结论

本轮确认可落地的结构是：

```text
MJPEG 采集与解码
        ↓
      I420
       ├─ 最新帧队列（深度 1）→ x264 ultrafast、2 线程 → H.264/RTP
       └─ 最新帧队列（深度 1）→ I420→BGR → ROS/视觉算法
```

建议保持 1080p/30 FPS；6 Mbps 用于正式画质，4 Mbps 只能在链路容量不足时作为降级档。安卓继续使用正式 `100/180` 策略。继续降低 Media3 缓冲只带来约 4–11 ms 的中位收益，却把短欠载增加到 18–46 次。

按此前约 300 ms 的光学测量推算，机载路径本轮减少约 28 ms 后仍大约在 270 ms 量级，不能宣称已经达到 200 ms。下一阶段若必须稳定接近 200 ms，需要在测试分支验证直接 RTP→MediaCodec 的播放器路径，绕开 Media3 RTSP 的约 160 ms 稳态媒体缓冲；之后再做同屏高速录像验收。

## 复现

机载容器中执行：

```bash
bash /workspace/test/camera_delay_optimize/run_test.sh I420_VISION 30 6000
```

参数依次为像素路径、测量秒数和码率 kbps。结果保存到 `test/camera_delay_optimize/results/`。
